## 1. Purpose of this quantum spawn

This document is the first part of a four-part engineering spawn specification for the Solar Electrical Topology Analysis Engine. Its purpose is to transfer the programme’s design intent into a form that a new ChatGPT thread, coding agent, engineer or reviewer can use without reconstructing the project from a long conversation history.

This is not a transcript. It is not a marketing summary. It is not a retrospective intended to justify every intermediate decision. It is an engineering handover that records what the programme is trying to become, why the current V11.2 direction exists, what architectural boundaries must be preserved, and which earlier lessons must not be forgotten.

The central problem is simple to state but difficult to model correctly:

> A utility-scale solar DC string is not merely a list of modules. It is a physical electrical installation composed of modules, junction-box terminals, factory leads, connector ends, mating interfaces, field cables, inverter sockets, routes, dimensions, polarity, evidence and engineering consequences.

Most solar design tools simplify that installation into symbols, string counts or route-length assumptions. That simplification is useful for high-level design, but it conceals the physical DC layer where failures, installation errors, connector incompatibilities, cable excess, loop area, resistance, voltage drop, induced surge exposure and commissioning ambiguity actually occur.

The programme exists to make that hidden layer explicit.

The long-term ambition is a topology engine capable of representing one complete inverter block and eventually much larger systems as a deterministic, evidence-backed electrical graph with physical geometry. The immediate V11.2 ambition is narrower and deliberately visual:

> Reproduce the clarity of the V8 sequential and leapfrog connection drawing, but expand it across the complete 24-string inverter block on one full-screen engineering plane.

That narrowing is intentional. V11.2 is not attempting to complete every analytical layer simultaneously. It is being created to establish the drawing authority first: every module, terminal, lead, connector, mate and inverter connection must be visible and traceable.

## 2. The programme thesis

The programme is governed by three statements:

**Topology defines what connects. Geometry defines where conductors run. Physics operates on explicit paths.**

These statements must remain separate.

Topology answers questions such as:

- Which positive connector mates with which negative connector?
- Which module is electrically before or after another module?
- Which two connector ends form a mating interface?
- Which free string end terminates at which inverter socket?
- Which physical DC input belongs to which MPPT?
- Does the string form one continuous unbranched series circuit?

Geometry answers different questions:

- Where is each module physically located?
- Where is the junction-box axis?
- Where do factory leads leave the module?
- What is the route of each field conductor?
- How long is each segment?
- What physical loop is enclosed by the positive and negative routes?
- Is a proposed leapfrog connection physically reachable?

Physics can only operate honestly after those two layers are explicit. Resistance requires conductor type and length. Voltage drop requires current and resistance. Loss requires current and resistance. Propagation delay requires path length and dielectric assumptions. Surge and electromagnetic calculations require physical routes and loop geometry. None of these should be derived from a decorative browser line whose coordinates were invented for appearance.

This is why the browser must not be the engineering authority. The browser should render authoritative objects; it should not create them.

The intended hierarchy is:

1. Evidence-backed component definitions.
2. Authoritative electrical topology graph.
3. Authoritative physical routing geometry.
4. Derived engineering calculations.
5. Browser, SVG, JSON, CSV, schedules and reports as projections.

V11.2 currently focuses on the fifth item as a drawing product, but it must remain faithful to the earlier layers. Its role is not to replace the graph. Its role is to make the graph legible.

## 3. Historical development

### 3.1 The early browser lesson

The programme emerged from repeated attempts to represent a solar inverter block in the browser. Several versions were useful, but they were useful for different reasons.

V7 established the value of a whole-inverter overview. It made strings, MPPTs, physical grouping and the broader array architecture visible. It was strong as a system-level map.

V8 established the visual language for module-level wiring. It showed fixed physical module positions and made the difference between Sequential and Leapfrog intelligible through actual connection paths. A reader could see where free ends appeared, which modules were skipped by longer connections, where the far-end return existed, and how leapfrog changed the external routing consequence.

V10 moved toward a broader authority model, but its browser diagrams became more symbolic and less faithful to the physical connection picture. The result could be analytically interesting while being less immediately useful to an installer or engineer tracing real conductors.

V11 was created to recover engineering authority. It introduced a stronger repository structure, deterministic validation, Python/browser parity, CI evidence, a 24-string reference block, browser testing and graph-oriented connector accounting. It also developed a full-array workbench and a module-layout environment.

Those achievements were real. However, the browser gradually drifted toward a compact logical overview. It showed module strips and traversal order, but the user’s core requirement was different: show the actual connector-to-connector wiring as clearly as V8, across all 24 strings.

The critical lesson is that a correct data model does not guarantee a correct engineering drawing.

### 3.2 What V8 got right

V8’s value was not decorative styling. Its value was explanatory precision.

It preserved physical module positions and changed the electrical connections. That made it possible to compare two topologies without confusing topology with geometry.

In Sequential wiring, the modules remain arranged M1 to M30. Adjacent modules are connected in sequence. The two free string ends appear at opposite physical ends, requiring an additional external return route when both inverter connections are located at one side.

In Leapfrog wiring, the same physical modules remain M1 to M30. The electrical order changes through odd modules outward and even modules returning. Longer inter-module connections cross over skipped modules. Both free string ends can be brought to the inverter side. The external far-end return can therefore be removed, subject to lead-length feasibility.

V8 made this understandable in seconds because it drew separate leads and joins. It did not replace the wiring with a single polyline labelled “Leapfrog”.

That exact property is now the visual target for V11.2.

### 3.3 Why V11 became visually confused

V11 accumulated several distinct product ideas:

- full inverter-block overview;
- electrical simulation;
- module layout editing;
- route estimation;
- browser diagnostics;
- connector schedules;
- evidence exports;
- mobile support;
- a live development monitor.

Each idea was defensible, but their combination caused the main page to behave like a dashboard rather than a drawing.

Compact rows were introduced to fit 24 strings. Module cells became small. A traversal polyline was used to communicate electrical order. Detail panels were constrained by mobile layouts. Text, metrics and controls competed with the schematic. The browser increasingly told the user about the topology instead of showing the topology.

The problem was therefore not a lack of code. The problem was an incorrect presentation boundary.

The engineering kernel was getting stronger while the drawing became less like the successful V8 reference.

V11.2 is the corrective response.

## 4. Why V11.2 exists

V11.2 is not a cosmetic revision of the existing workbench. It is a separate product surface with a narrower purpose.

Its scope is:

> Draw the complete DC electrical connections for one 24-string inverter block as one full-screen, SCADA-like engineering schematic.

It should feel closer to electrical CAD or a control-room schematic than to a conventional web dashboard.

The V11.2 branch is `build/v11.2-full-array-sld`, and the drawing surface lives under `v11.2/` in the `Ventusltd/v11` repository.

The decision to create a separate surface avoids forcing one page to satisfy incompatible goals. The existing V11 work can retain simulation, testing, graph logic and broader experiments. V11.2 can remain disciplined around drawings.

V11.2 should not contain:

- metric-card grids;
- long technical commentary;
- general-purpose widgets;
- random module dragging;
- layout packing;
- marketing content;
- decorative animations;
- broad physics analysis;
- unnecessary panels.

It should contain:

- the inverter and its 24 DC inputs;
- 12 MPPT groupings;
- 24 strings;
- 30 modules per string in the reference case;
- centre-positioned module junction-box geometry;
- factory leads;
- connector ends;
- mating interfaces;
- field cables;
- polarity markers;
- labels, IDs and dimensional evidence;
- minimal controls for wiring mode and view scale.

The primary test is not whether the page looks impressive. The primary test is whether an engineer can trace every connection without inference.

## 5. Manufacturer geometry as drawing evidence

The current reference module is the Trina Solar TSM-DEG21C.20 bifacial dual-glass module in the 645–665 W family.

The Trina datasheet, Version `TSM_EN_2024_A`, gives the following relevant mechanical information on page 2:

- module dimensions: 2384 × 1303 × 33 mm;
- 132 cells;
- IP68 junction box;
- portrait factory cable lengths: 350 mm and 280 mm;
- cable length can be customised;
- connector family stated as MC4 EVO2 / TS4, subject to the regional datasheet;
- the back-view drawing places the cable/junction-box axis through the central horizontal region of the module.

The drawing therefore must not place generic connectors arbitrarily at the outer module corners merely because that is convenient for a browser renderer.

The module symbol should preserve the real proportion and centre J-box axis as geometric evidence, while still allowing a not-to-scale SLD projection where necessary for legibility.

This produces an important distinction:

- actual manufacturer dimensions are authoritative metadata;
- screen coordinates are a projection;
- the transformation between them must be documented.

For example, every module SVG object should be capable of exposing data attributes for actual width, height, J-box axis position and lead datum even if the screen view enlarges connector spacing for clarity.

The programme must also avoid unsupported inference. The datasheet does not, by itself, fully establish the delivered connector gender or the exact positive/negative root side for every regional product configuration. Those properties must remain unverified until supported by manufacturer-specific evidence.

## 6. Architectural boundaries

### 6.1 Component authority

The component layer defines what physical things exist.

At minimum, the eventual model includes:

- module;
- junction box;
- positive and negative module terminals;
- positive and negative factory leads;
- connector ends;
- mated connector interfaces;
- positive and negative string cables;
- inverter DC sockets;
- physical DC inputs;
- MPPT groups.

Each component needs a stable identity. A connector cannot be “the blue dot near M17”. It must be a connector object with an ID.

### 6.2 Electrical graph authority

The electrical graph defines connectivity.

For every connector end, the graph should identify:

- component ownership;
- polarity;
- mate;
- mating-interface ID;
- source and destination relationship;
- string;
- MPPT;
- physical inverter input;
- evidence state.

A complete 30-module string contains:

- 60 module connector ends;
- 4 string-cable connector ends;
- 2 inverter connector ends;
- 66 connector ends in total;
- 29 module-to-module mating interfaces;
- 2 module-to-string-cable interfaces;
- 2 string-cable-to-inverter interfaces;
- 33 mating interfaces in total.

A complete 24-string block therefore contains:

- 720 modules;
- 1,584 complete-system connector ends;
- 792 mating interfaces.

Sequential and Leapfrog use the same physical connector-end population. What changes is which module connector ends mate with which other module connector ends.

This is a fundamental invariant.

### 6.3 Drawing projection

V11.2 converts the graph into SVG.

Every visible connection path must be generated from source and destination IDs. A path must terminate at the exact connector node. The browser must not infer a mate because two modules are adjacent, because one label follows another, or because a connector happens to be nearest on screen.

The drawing projection may choose the curvature, offset and lane of a path to make the schematic legible. It may not choose the electrical endpoints.

### 6.4 Physical routing

The V11.2 first milestone is the SLD drawing, not a completed project route design.

Factory leads and module-to-module connections are shown as physical interconnects associated with module geometry. Field home-run conductors may initially be schematic, but they must be visibly distinct as black cables joining free string ends to inverter sockets.

A later physical routing graph will define route vertices, segment lengths and loop geometry. Until that graph exists, V11.2 should identify route geometry as schematic rather than silently presenting it as measured.

## 7. Design philosophy

### 7.1 Show, do not explain

The schematic should answer the question visually.

A user should not need a paragraph explaining that leapfrog connects odd modules outward and even modules back. The drawing should make each long hop and the far-end crossover visible.

Text should identify, not compensate for missing geometry.

### 7.2 Accuracy before decoration

The priority order is:

1. Correct electrical endpoints.
2. Correct component identities.
3. Correct manufacturer dimensions and datums.
4. Correct polarity markers.
5. Correct topology.
6. Readable scale and spacing.
7. Visual polish.

Gradients, shadows and animation are irrelevant if the connector lands on the wrong module.

### 7.3 Black cables, polarity at connectors

Factory and field PV cable jackets are black.

Red and blue are not cable colours in this drawing system. They are polarity markers at connector ends and terminations:

- red marker: positive;
- blue marker: negative;
- black line: physical cable;
- orange block: inverter equipment.

This preserves the physical appearance of EN 50618-type PV cable while making polarity immediately visible.

### 7.4 Fixed geometry, changing topology

Module positions remain fixed when the user changes between Sequential and Leapfrog.

This prevents the drawing from cheating by rearranging modules to make the wiring easier to show.

The comparison must reveal the actual consequence of changing electrical mates while retaining the same physical row.

### 7.5 One plane

The complete 24-string inverter block should exist on one continuous plane.

The user may pan and zoom. The browser may provide Fit Width and 100% controls. It should not break the system into unrelated cards, widgets or modal fragments.

The full plane should preserve:

- MPPT group context;
- string identity;
- inverter input identity;
- module order;
- connector identity;
- connection paths.

### 7.6 Evidence over confidence

Every sensitive property should have an evidence state.

Manufacturer dimensions may be manufacturer-declared. Connector gender may be unverified. Custom lead lengths may be project-declared or assumed. Route coordinates may be schematic. A first-article fit test may later convert a design assumption into measured evidence.

The engine should never make an unsupported assumption look authoritative merely because it can draw it convincingly.

## 8. Product identity

V11.2 is not another generic solar layout tool.

It is not trying to compete on automated roof packing, terrain optimisation or sales proposals.

Its identity is the explicit physical DC layer:

- real string topology;
- real connectors;
- real module geometry;
- real cable paths;
- real inverter terminations;
- traceable evidence;
- deterministic validation.

The intended users include:

- solar electrical designers;
- owner’s engineers;
- EPC engineers;
- commissioning engineers;
- O&M teams;
- cable and connector specialists;
- inverter and module manufacturers;
- technical investors investigating design and failure risk.

The distinctive promise is that a user can inspect the exact electrical installation rather than a summary abstraction.

## 9. Definition of success for the first drawing milestone

The first V11.2 milestone succeeds when the browser can display the complete 24-string reference inverter block and a competent engineer can verify the following without reading implementation code:

- there are 24 strings;
- each string contains 30 modules;
- the strings are grouped into 12 MPPTs;
- every module has a centre-positioned J-box representation;
- every module exposes positive and negative connector ends;
- every module-to-module mate is visible;
- Sequential and Leapfrog preserve module positions;
- Sequential and Leapfrog show different mating pairs;
- the free ends are visible;
- both string cables are visible;
- inverter positive and negative sockets are visible;
- all cable bodies are black;
- positive and negative markers are red and blue;
- no connection floats near a connector without terminating on it;
- the full array can be panned and zoomed on one plane;
- the drawing remains legible on desktop and mobile through horizontal and vertical navigation rather than compression.

The first milestone does not require completion of every resistance, route, surge or earthing calculation. Those belong to later layers.

It does require that the drawing is honest about what is authoritative and what remains schematic.
